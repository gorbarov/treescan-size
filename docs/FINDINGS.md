# Заключение: как дешёвые модели написали мак-приложение

Эксперимент 24–25.09.2026. Нативное мак-приложение TreeSize («чем забит диск») написали дешёвые модели DeepSeek V4 Flash (coding-lite через your-gateway.example) по заданиям Claude Opus. Claude кода приложения не писал: только ТЗ, задания, проверки и приёмку. Подробный журнал по ходу — [RESEARCH.md](RESEARCH.md).

## Короткий ответ

**Справляются — если их правильно кормить и проверять.** Результат — работающее приложение на Swift/SwiftUI: 4,7 тыс. строк, 19 файлов интерфейса, `.app` с иконкой и подписью. Внешне очень близко к HTML-макету: дерево с полосками, круговая диаграмма, пять вкладок, контекстное меню, выбор диска, светлая и тёмная тема.

Цена — **≤204 ₽** по верхней оценке, и это считая кэш по полной цене. Кэш — 91 % входа. Если шлюз берёт за кэш в 10 раз дешевле, как сам DeepSeek, то **≈50 ₽**. Точную цифру показывает кабинет шлюза.

| | прогонов | ходов | машинного времени | токенов вход / выход | ≤ ₽ |
|---|---|---|---|---|---|
| Claude Code (оболочка) | 9 | 556 | 3,5 ч | 22,9 млн / 0,66 млн | 67 |
| Pi (оболочка) | 19 | 651 | 3,7 ч | 50,4 млн / 0,68 млн | 136 |
| **Всего** | **28** | **1 207** | **7,2 ч** | **73,4 млн / 1,35 млн** | **204** |

Pi в сумме дороже только потому, что сделал больше заданий (05–12) и длинные доработки. На одинаковых заданиях он дешевле (см. «Оболочки»).

## Что дешёвая модель делает хорошо

- **Переносит логику по эталону.** Сканер на Swift совпал с Python-версией байт в байт на тестовой папке, «Загрузках» и всём Dropbox.
- **Верстает по спецификации на 70–80 % с первого захода** — дерево, диаграмма, таблицы, тёмная тема.
- **Честно считает.** Ни разу не подогнал ответ под ожидаемые числа, проверено grep-ом.
- **Быстро чинит по точному замечанию.** Доработка со скелетом кода — 2–4 минуты и 1,5–2 ₽.

## Где без сильной модели было бы плохо

1. **Тихие логические ошибки при зелёных тестах.** Пересчёт после удаления (задание 03), порядок топа файлов — проходили проверки, ловились только чтением кода или по снимку.
2. **Безопасность.** В меню корзины своё свойство `isProtected` перекрыло функцию защиты системных папок. При скане всего диска можно было отправить в корзину домашнюю папку. Проверки и снимки этого не видели, нашло только ревью опасного кода.
3. **Вёрстка словами не доходит.** Кольцо диаграммы два раза выходило не того размера. Помог только скелет кода на 10 строк.
4. **Исследовательские задачи без готового пути.** Живая проверка кликов (10u): DeepSeek час перебирал подходы и остановился по сторожу. Здесь решение упирается в среду (SwiftUI, песочница, разрешения macOS), а не в код.
5. **Дисциплина.** Забывает коммит, может перезаписать файл целиком вместо дописывания, иногда ломает то, что работало в прошлом задании.

## Рецепт: как с ними работать

1. **Резать на задания по 10–40 минут** с одной понятной проверкой каждое. Длинная сессия дорожает: каждый ход заново читается вся переписка.
2. **Проверка с заранее посчитанным ответом** (эталонная реализация, `expected/*.json`). «Кажется, работает» — не проверка. Нормализацию в тестах — минимальную: она прячет ошибки порядка.
3. **Эталон дизайна — снимками.** Модель рисует окно, приёмщик сравнивает снимок с макетом глазами. Снимок интерфейса оказался лучшим сквозным тестом: поймал ошибку сканера через пять заданий.
4. **Вёрстку — скелетом кода, логику — ссылкой на функцию эталона.** Словесные описания раскладки дешёвая модель понимает хуже, чем 10 строк готового кода.
5. **Абсолютные пути и явные запреты** в прологе задания: куда смотреть, что нельзя трогать, «коммить обязательно», «отчёт только дописывать».
6. **Ревью опасного кода — всегда вручную**: удаление, права, внешние действия. Тесты зелёные — не аргумент.
7. **Доработку — в ту же сессию** (`--resume`), пока она короткая. Разросшуюся лучше начать заново: дешевле.
8. **Исследовательские развилки — сильной модели.** Дешёвая хорошо идёт по проложенному пути и плохо его ищет.
9. **Песочница и сторож обязательны**: запись только в проект, запрет удаления и сети, остановка после 10 минут тишины или часа работы.

## Оболочки: Claude Code против Pi

Два сравнения на одинаковых заданиях с одной стартовой точки, модель та же:

| | Claude Code | Pi |
|---|---|---|
| Задание 05 (дерево) | 44 хода, 23 мин, ≤6,3 ₽, полоса поверх текста | **29 ходов, 8,7 мин, ≤4,1 ₽, ближе к макету** |
| Задание 08 (таблица) | 86 ходов, 12 мин, ≤10 ₽ | **29 ходов, 9,7 мин, ≤3,2 ₽**, качество равное |
| Песочница | встроенная, сеть не режет | через `pi-sandbox`, **строже** (режет сеть и чтение секретов) |
| Дисциплина | коммитит, дописывает отчёт | **забывает коммит, перезаписывает файлы** |
| Запреты | из коробки (`permissions`) | пришлось дописать расширение-сторож на 30 строк |

**Вывод:** для дешёвой модели Pi выгоднее — в 1,5–3 раза меньше ходов и денег. Правдоподобная причина — короткий системный промпт. Слабое место — дисциплина, закрывается правилами в прологе. Другие кандидаты на будущее — **mini-swe-agent** (одна команда bash, ей меряют модели в SWE-bench) и **Aider** в режиме architect.

## Что не проверено

- **Клики мышью внутри панелей** (дерево, вкладки, легенда) — автоматом проверить не удалось: нужны руки или разрешение «Универсальный доступ». Кнопки и клавиатура подтверждены.
- **Корзина и «не синхронизировать» на настоящих файлах** — по договорённости проверяет CEO.
- **Скорость интерфейса на всём диске** (170 тыс. узлов). Сканер на таком объёме проверен, интерфейс — нет.
