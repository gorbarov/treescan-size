# TreeSize.app — что строим

Настоящее мак-приложение вместо связки «Python-скрипт + браузер». Поведение уже есть и проверено у CEO в эталонной реализации [reference](../reference/README.md). Приложение повторяет его без Python, без браузера и без локального сервера.

## Главное решение (обновлено 24.09.2026): полностью нативный интерфейс

CEO выбрал вариант Б: интерфейс тоже на Swift (SwiftUI). HTML-отчёт [template.html](../reference/template.html) — эталон дизайна и поведения, но в приложение не встраивается. Подробно — [UI-SPEC.md](UI-SPEC.md).

- **TreeSizeCore** (готово на этапе 1): сканер → `data`. Сверху ложатся модель `Node`/`ScanResult`, форматы и действия над файлами.
- **TreeSizeApp**: SwiftUI-приложение — дерево с полосками, круговая диаграмма (Charts), таблицы, контекстное меню, выбор диска.
- Код пишут дешёвые модели (coding-lite: DeepSeek V4 Flash и другие) маленькими заданиями из `docs/tasks/`. У каждого задания есть автоматическая проверка `tools/check_task.sh NN`. Приёмка и документация — Claude.

Раздел «Протокол моста» ниже больше не нужен: мост JS ↔ Swift был для варианта А. Оставлен для истории, действия те же.

## Ограничения

- macOS 14+, Apple Silicon. Сборка через Command Line Tools (`swift build`), **Xcode не установлен**. Проект — Swift Package, без `.xcodeproj`. XCTest недоступен, проверки — скриптами.
- Без App Store и песочницы. Подпись ad-hoc (`codesign -s -`), приложение только для CEO. Аккаунт Apple Developer не нужен.
- Никаких сторонних зависимостей: только Foundation, AppKit, SwiftUI, Charts, Darwin.
- Сборка идёт в `/tmp/ts-build` (вне Dropbox), готовое приложение — в `build/`: эта папка исключена из синхронизации Dropbox атрибутом.

## Формат данных (JSON, как у treesize.py)

```text
data = {
  root:    "/abs/path",               // что сканировали
  host:    "имя мака",
  scanned: "YYYY-MM-DD HH:MM",
  took:    12.3,                      // секунды, число с одним знаком
  errors:  0,                         // сколько раз не удалось прочитать папку или файл
  stuck:   ["/path", ...],            // папки, которые не ответили за timeout
  tree:    node,
  top:     [[size, path, alloc, cloud, mtime], ...],    // до 1000 крупнейших файлов, по убыванию
  ext:     [[ext, size, count, cloud], ...],            // по убыванию size
  age:     [[label, size, count], ...],                 // 6 корзин, порядок фиксирован
  dups:    [[size, [path, path, ...]], ...],            // до 300 групп, по убыванию size*(n-1)
  dupMin:  5242880,
  api:     "app"                      // есть только в отчёте, открытом в приложении
}
node = [type, name, size, alloc, cloud, files, dirs, mtime, ign, children?]
  type:  0 папка, 1 файл, 2 сводка «[N файлов и M папок помельче]» (name = "")
  size:  логический размер, байты (st_size)
  alloc: занято на диске (st_blocks * 512)
  cloud: байты файлов «только в облаке» (флаг SF_DATALESS 0x40000000 в st_flags)
  files, dirs: сколько файлов и папок внутри, рекурсивно
  mtime: самая свежая дата изменения внутри, целые секунды unix; 0 — нет
  ign:   байты внутри с пометкой Dropbox «не синхронизировать»; -1 — помечена сама папка
  children: есть только у папок с содержимым
```

Точные правила — в коде эталона, функции `Scanner.scan`, `Scanner.account`, `serialize`, `scan_root`. При расхождении описания и кода прав код эталона, а `tools/compare.py` — судья.

## Протокол моста

JS вызывает `window.webkit.messageHandlers.treesize.postMessage({action, path?})` и ждёт ответ-объект `{ok: true|false, error: "текст"|null, ...}`.

| action | что сделать | ответ сверх ok/error |
|---|---|---|
| `progress` | состояние текущего скана | `files`, `bytes`, `cur` (текущая папка) |
| `places` | диски и типовые папки | `places: [{kind:"disk", name, path, total, free} \| {kind:"folder", name, path}]` |
| `choose` | системный диалог выбора папки | `path` или `null` при отмене |
| `rescan` | пересканировать текущий корень | — |
| `scan` | просканировать `path` (папка должна существовать) | — |
| `reveal` | показать `path` в Finder | — |
| `trash` | переместить `path` в корзину | — |
| `ignore` / `unignore` | поставить или снять атрибут Dropbox на `path` | — |
| `copy` | положить `path` (здесь это просто текст) в буфер обмена | — |

После успешных `scan` и `rescan` страница сама вызывает `location.reload()`. Значит, к моменту ответа новый отчёт уже должен лежать в том же файле, из которого загружена страница.

Проверки перед `reveal`, `trash`, `ignore`, `unignore` (как в `serve()` эталона):
- путь лежит внутри текущего корня и не является самим корнем;
- путь существует (`lstat`);
- для `trash` путь не защищён — функция `protected()` эталона.

## Что должно получиться у CEO

1. Двойной клик по TreeSize.app сканирует последнюю открытую папку. При первом запуске — Dropbox, если он есть, иначе домашнюю папку. Пока идёт скан, видно прогресс.
2. Работает всё, что есть в отчёте через `TreeSize.command`: дерево, двойной клик, диаграмма, вкладки, правый клик, корзина, «не синхронизировать», «Открыть…», «Пересканировать».
3. Меню приложения: «Открыть…» ⌘O, «Пересканировать» ⌘R, «Закрыть» ⌘W, «Выйти» ⌘Q, стандартное меню «Правка» (⌘C/⌘V в поле пути).
4. Иконка приложения в духе логотипа отчёта: три цветных квадрата.
