# Доработка к 18а: зависание вкладки «Дубли»

Замер 28.09 на всём диске (2,86 млн файлов): скан 98 с, потом вкладка «Дубли» отрисовывается **9 минут**, приложение висит. Причина — `Node.findDescendant(by:)` в `Sources/TreeSizeCore/Model.swift`: обход всего дерева в глубину. `NodeMenu(path:store:)` вызывает его в `init` для каждой из ~1000 строк дублей (и топа) при каждой перерисовке, а большинство этих файлов свёрнуты в «помельче» — поиск не находит ничего и каждый раз проходит всё дерево.

1. `findDescendant(by:)` — спуск только по префиксу пути: на каждом уровне идти только в того ребёнка, для которого `target == child.path` или `target.hasPrefix(child.path + "/")`. Если такого нет — `nil`. Никакого полного обхода. Если в 18а ты уже сделал `AppStore.node(at:)` — пусть оба используют одну реализацию.
2. `NodeMenu(path:store:)` — не искать узел в `init`. Сделай `node` ленивым: вычислять при построении `body` меню (оно строится при открытии меню), а не при создании строки.
3. Проверка в `--selftest`: факт — на `/tmp/ts-fixture` `findDescendant(by:)` находит `/tmp/ts-fixture/media/film.mov` и возвращает `nil` для `/tmp/ts-fixture/nope/x` и для файла, свёрнутого в сводку. Плюс факт на скорость: 10 000 вызовов `findDescendant` с несуществующим путём на фикстуре — меньше 0,5 с.
